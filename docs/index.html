Real-time Packet Monitoring & Traffic Statistics

A command-line traffic analysis pipeline: capture packets offline from a .pcap file or live from a network interface, dissect Ethernet, IPv4, TCP, UDP, ICMP, DNS and HTTP headers, aggregate per-protocol and per-endpoint statistics, and export them as CSV, charts and a Markdown report. The console below is a static build of the same dissection and aggregation rules running entirely in your browser.

What the pipeline does

One pass over the capture produces a typed record per packet; the statistics layer then aggregates them. The same structure is visible in the browser console above.

Dissection

  • Link layer — Ethernet source and destination addresses, EtherType, 802.1Q VLAN tags.
  • Network layer — IPv4 addresses, TTL, protocol number; fragments are dissected but not reassembled.
  • Transport layer — TCP and UDP port pairs; TCP control flags; ICMP classified by type.
  • Application layer — DNS question names and HTTP request or response lines.
  • Stream extraction — classic .pcap headers (little- and big-endian, microsecond and nanosecond timestamps), with link-type handling kept explicit.

Aggregation and output

  • Summary metrics — packet and byte totals, mean packet size, capture duration, mean and peak packets per second.
  • Distributions — protocol mix with shares, top source and destination addresses, top source and destination ports with service labels, top DNS queries.
  • Per-second series — bucket counts used for the rate chart and the peak-second metric.
  • Exports — packet-level CSV, protocol pie chart and endpoint bar charts as PNG, and a Markdown report.
  • Terminal dashboard — Rich tables for the same numbers, printed as the run finishes.

Run it locally

The command-line pipeline is the primary interface; the page above is the hosted demo of its logic.

Install

git clone https://github.com/TeWei02/Real-time-Packet-Monitoring-and-Traffic-Statistics-System.git
cd Real-time-Packet-Monitoring-and-Traffic-Statistics-System
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

Usage

# analyse a capture file and print the dashboard
python main.py --mode offline --pcap sample_data/demo.pcap

# regenerate the synthetic capture, then analyse and export CSV / charts / report
python main.py --demo --export

# live capture (needs the privileges the capture device requires)
sudo python main.py --mode live --iface en0 --limit 500

  • The browser build is diffed against the Python reference in the console above.

Scope, evidence and limitations

The project reports properties of the captures it is given. It does not infer user identity, content or intent, and it does not claim to classify application traffic.

What the numbers on this page are

  • Bundled capture — synthetic packets generated by the project's own demo generator; addresses, ports and DNS names are fabricated.
  • Synthetic stream — generated in your browser from a fixed seed, labelled simulated in the interface and in the exported report.
  • Uploads — your own file, parsed locally; nothing is transmitted and nothing is stored.
  • Python reference — produced by the Scapy pipeline on the same capture; the comparison table shows every quantity checked.

Known limitations

  • Statistics describe packet headers only; no payload reconstruction or session reassembly.
  • IP fragments are dissected but not reassembled, so fragment offsets are not reflected in the aggregates.
  • HTTP detection matches request and status lines at the start of a TCP payload; it is not a full HTTP parser.
  • DNS is dissected for port 53; responses without a question section are counted as DNS with no query name.
  • Live capture requires the permissions the capture device needs, and is unavailable in the browser build.
  • The browser build reads classic .pcap only; pcapng files are rejected with a message.

Offline use

The page registers a service worker, so once it has been visited it works without a network connection and can be installed to the home screen from a mobile browser. Reload once after the first visit to confirm the cached copy.
